\section*{Questions}



Phase 3 left five things open. Phase 4 took them in priority order:



\begin{enumerate}
\item \textbf{Complexity (B):} is there a harder task the MLP learns, on which TRM's relative deficit shrinks (H1$'$)?
\item \textbf{Training discipline (A):} does restoring TRM's own training (no gradient truncation, per-cycle supervision) change the result?
\item \textbf{Tuning (C):} was TRM simply never tuned?
\item \textbf{Algorithm (T, added mid-phase):} does Phase 3's central attribution hold under TD3 as well as DDPG?
\item \textbf{Mechanism and deployment (E, D):} is TRM's noise sensitivity explained by a sharper input--output map? Do the actors fit a 512 KB microcontroller?
\end{enumerate}



\section*{Methodology}



\begin{itemize}
\item \textbf{Pre-registration.} Every stage's arms and decision rule were written into \texttt{plan.md} and \texttt{gates.json} before its data. Later changes are dated amendments, each made before the data it affects: R-1, R-2, V-1, A-1, K-1, K-2, T-1, K-3. The author approved every main matrix after seeing a job count and walltime estimate.
\item \textbf{Code changes behind default-off flags:}
\begin{itemize}
\item \texttt{arch.\allowbreak{}total\_\allowbreak{}steps}, an env-step budget;
\item \texttt{model.\allowbreak{}full\_\allowbreak{}grad}, \texttt{model.\allowbreak{}deep\_\allowbreak{}sup} on the TRM trunk;
\item \texttt{arch.\allowbreak{}\{actor,\allowbreak{}critic\}\_\allowbreak{}grad\_\allowbreak{}clip}, gradient clipping with norm logging.
\end{itemize}
\item \textbf{Verification before any data (V-1):}
\begin{itemize}
\item a gradient-hook test: 7/21 cell applications receive gradient truncated, 21/21 with \texttt{full\_grad};
\item all 30 existing trunk $\times$ algorithm $\times$ condition configurations bit-identical (weights and histories) to the pre-Phase-4 code;
\item Stage A's MLP reuse checked against the exact Phase 3 snapshot (R-1);
\item one GPU smoke job.
\end{itemize}
\item \textbf{Execution.} Katana PBS, every job from a frozen per-stage code snapshot, logged in a ledger, with a live run board.
\item \textbf{Statistics.}
\begin{itemize}
\item Pairs matched by seed (and condition when pooled to n = 12).
\item Sign tests, with k/n and two-sided p.
\item Gates at $\geq$ 5/6, or $\geq$ 10/12 pooled.
\item Final avg-100 training return is primary; eval last-5 and the battery are secondary.
\end{itemize}
\end{itemize}

\section*{Discussion}



\begin{itemize}
\item \textbf{TRM was not untuned (GC).} The default learning rates are near the best of a 9-cell grid, and TRM's critic loss stays well above the MLP's in every cell. Phase 3's deficit is not a tuning artefact within $\times$0.3--$\times$3.
\item \textbf{The training discipline does not rescue it (GA).}
\begin{itemize}
\item Giving gradient to all 21 cell applications, and supervising every cycle's critic readout, leaves return and value fit essentially where truncated TRM was.
\item That separates "untrained depth" from the deficit. Depth was inert in Phase 3 because the cell gets no new information between passes, not merely because it got no gradient.
\item Compare Tiny Recursive Control (Jain \& Linares, 2025): there, every pass receives the error from simulating its current answer, so iteration has something to correct.
\end{itemize}
\item \textbf{The direction of G1 survives a second algorithm (GT), but the magnitude does not replicate.}
\begin{itemize}
\item Under TD3's standard settings the MLPs train as well as under DDPG.
\item TRM 788k mostly fails to train at all; its critic loss rises through training.
\item In practice this is evidence against TRM: it is harder to optimise and needs care the MLP does not. It is not a replication of "loses by about 30 units".
\item The likely contributor, \texttt{td3.yaml}'s 10$\times$ higher actor learning rate, is untested.
\end{itemize}
\item \textbf{Complexity stays untested.} InvertedDoublePendulum is learnable without delay, but the one-step delay keeps the MLP unreliable even at 1M steps, and Hopper never reached its bar. No harder task gave a usable baseline, and with TRM untrainable under TD3 a B1 run would have measured that failure instead. This is a limitation of the evidence, not evidence against TRM.
\item \textbf{Robustness is not explained by local sensitivity (E).} TRM's policies react \emph{less} sharply to small input changes yet degrade more under finite sensor noise. Whatever makes TRM less robust is not captured by its local Jacobian.
\end{itemize}

\textbf{Bottom line:} within the settings tested, TRM's weight-tied recursion brings no consistent benefit as a model-free actor-critic trunk. Five ways of rescuing it have now failed: capacity, depth, memory, tuning and training discipline. Under a second algorithm it is harder still to train. \textbf{Use the MLP.}
